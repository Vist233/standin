# @standin/router

Turns signals (a user message, a mail, a timer, a finished sub-agent) into deliveries for the runtime: **start a run**, **steer** the running one, or **stop**. A pure state machine: no clock, no I/O, no randomness.

- **Interface:** `new Router({ mergeWindowMs?, retryDelayMs?, rememberedIds? })`; `handle(input) -> { deliveries, decisions }` for the inputs `signal`, `stop`, `run-started`, `run-finished`, `delivery-acked`, `delivery-failed`, `tick` (all JSON, all carry `at`); `nextWakeup()` (when to send a `tick`); `inspect(sessionId)`. `@standin/router/testing` has `FakeClock` and `SimulatedRuntime`, a small model of the runtime's side of the protocol that the property tests drive.
- **Hides:** the queue and its ordering, duplicate memory, merge windows, retry pauses, the text format of a delivered signal.
- **Never knows:** HTTP, files, agents, the framework, real time. The caller supplies `at` and reports run state.
- **Rules (each has a test):** one run per session at a time (a start waits for `run-started`); idle → the signal starts a run, active → `steer` (the framework drops a steer when no run is active, so the router decides); the user's messages go ahead of what has not left, Stop is delivered at once and holds the session (nothing is deleted; nothing leaves the queue until the user writes again, and then the waiting signals follow the user's message in order), the rest keeps arrival order; quick signals of one source may be merged; an id is accepted once per session; a delivery that was not consumed (failed, or the run ended first) returns to its old place, after a pause when it failed; trust and priority come from the source, never from the producer (`user` and `system` are trusted, everything else is not); outside text is quoted line by line behind a one-line header.
- **Protocol the runtime must keep:** report in order; `delivery-acked` means the model read the steer (it is in the conversation), not that it was handed over; report `run-finished` also when the run died. A steer lost without a report is the one failure the router cannot see.
- **Replay:** inputs are plain JSON and the router is deterministic, so journalling inputs and feeding them back rebuilds the state, including the duplicate memory.
- **Limits:** duplicate memory keeps the last `rememberedIds` (10000) ids per session; a retry older than that is not recognised. Addressing is by `sessionId` given by the caller.
